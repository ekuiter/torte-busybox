# BusyBox feature-mapping scan

Assisted-by: LLM (Codex GPT-5.6 Sol, Qwen 3.5 9B)

`scan_busybox_feature_mappings.py` sends every commit reachable from `HEAD` to a
locally running LM Studio model in a separate, stateless chat-completion request.
It looks for clean Kconfig feature renames, splits, and merges matching Clausy's `--variable-map` format.
It runs on this repository's `master` branch.

## Recorded experimental setup

The complete BusyBox scan was run locally with the following setup:

- Processor: Apple M3 Pro, 12 CPU cores (6 performance and 6 efficiency cores)
- GPU: integrated Apple M3 Pro, 18 cores, Metal 3
- Unified memory: 18 GB
- Model: Qwen 3.5 9B, model ID `qwen/qwen3.5-9b`
- Model format and quantization: GGUF, `Q6_K` (approximately 8.28 GB)
- Loaded context length: 32,768 tokens
- Reasoning: disabled with `--reasoning-effort none`
- Sampling temperature: 0.1
- Maximum patch evidence: 60,000 characters, reduced automatically when needed
- Maximum completion: initially 1,800 tokens; increased to 8,000 for failed
  candidate-heavy commits and made the new default

- Total measured analysis time: 3h 1m 43.669s
- Mean: 7.85s per commit
- Median: 3.548s
- Minimum: 0.078s
- Maximum: 2m 50.791s
- Including all failed/retried attempts—1,399 records total—the measured time was 3h 18m 42.149s.

Each commit is processed in a separate stateless request. Merge commits are
compared with their first parent.

One exact bulk case is handled deterministically instead of asking the model to
emit an impractically large response: if at least ten old symbols all have a
`CONFIG_` prefix and stripping it creates an exact bijection with all new symbols,
the script expands that rule into individual rename candidates. The JSONL record
labels this as `"analysis_method": "deterministic_bulk_prefix_rename"`; all other
records use `"analysis_method": "lmstudio"`.

## Run

1. Start LM Studio's local server (normally `http://127.0.0.1:1234`) and load an
   instruction model with structured-output support. Use at least a 32K context
   window; the script warns and conservatively truncates evidence if the loaded
   context is smaller.
2. Test a few commits:

   ```sh
   python3 scan_busybox_feature_mappings.py --limit 5
   ```

3. Resume and scan all remaining commits:

   ```sh
   python3 scan_busybox_feature_mappings.py
   ```

Specify `--model MODEL_ID` if more than one model is loaded. Use
`--max-diff-chars` to change the evidence window, `--retry-errors` to re-run API
failures, and `--help` for all options. Interrupting is safe: one JSONL record is
flushed after every commit, and later runs skip completed commits.

To rerun only commits whose latest JSONL record has `"status": "error"`, use the
same model and output directory with `--retry-errors`. Successful commits are not
reprocessed, and new records are appended so the audit history is preserved.

`results.jsonl` is append-only. After a run, `candidates.csv` and all confidence
directories below `clausy-maps/` are regenerated from the latest record for every
commit. This does not discard successful analysis results: unchanged successes
remain in the regenerated files, successful retries replace the effective error
records, and stale map files are removed. The older JSONL records remain available
as an audit trail. Because CSV and map files are generated artifacts, any manual
edits made directly to them are overwritten; keep manual annotations elsewhere.

Reasoning is disabled by default (`--reasoning-effort none`) because Qwen can
otherwise spend the entire output allowance thinking and return no JSON. The
model variant, quantization, and loaded context reported by LM Studio are printed
at startup and recorded with each result.

## Outputs

The default output directory is `lmstudio-feature-mappings/` (unreviewed):

- `results.jsonl`: complete audit trail, including empty results, rejected model
  output, prompts' old/new symbol sets, model id, and timing.
- `candidates.csv`: compact manual-review queue.
- `clausy-maps/{possible,likely,very_likely}/<commit>.map`: directly parseable
  Clausy mappings, separated by confidence. These are candidates and must be
  manually reviewed before use.

Mappings are directional from the parent model to the commit model:

```text
OLD=NEW                 # rename
OLD=NEW_PART_1,NEW_PART_2  # split
OLD_PART_1,OLD_PART_2=NEW  # merge
```

For merge commits the first parent is the comparison baseline. For the root
commit the baseline is Git's empty tree. Rebuild the derived CSV and map files
without contacting LM Studio with `--export-only`.

## Review

Every candidate was reviewed by a human. The reviewed mappings and review results are available in `reviewed-mappings.zip`.
The review interface was generated by Codex and can be run with `python3 review-ui/server.py`.
